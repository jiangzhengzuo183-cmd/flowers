# 三人小组协作流程

## 1. 分支约定

- `main`：稳定主分支，只合并已检查的成果。
- `feature/story`：叙事、对话与开场剧情。
- `feature/exploration`：横向探索场景与场景切换。
- `feature/maze`：迷宫、阿尔吉侬移动、追逐与通关逻辑。
- `feature/report`：进步报告编辑器与文本变化。
- `feature/evidence`：退化线索、证据收集与证据板。

分支可按实际任务拆分；不要让两个人同时在同一分支上工作。分支名只是建议，创建前先检查是否已存在。

## 2. 每次开发的标准流程

1. 在 GitHub Desktop 切换到 `main`。
2. Fetch / Pull，获取最新主分支。
3. 从最新 `main` 创建自己的功能分支。
4. 在该分支上用 Codex 开发，只修改负责范围。
5. 在本地运行和检查改动。
6. Commit，并 Push 到 GitHub。
7. 创建 Pull Request，说明改动内容、测试结果、影响文件和接口变化。
8. 由整合负责人检查并测试，确认后合并。
9. 合并后，所有成员回到 `main` 并 Pull 最新版本，再开始下一项工作。

## 3. 文件所有权建议（待团队确认）

| 模块 | 主要内容 | 建议负责人 |
|---|---|---|
| 叙事与场景 | 对话、剧情推进、横向探索、场景切换 | 成员 A |
| 迷宫玩法 | 迷宫地图、移动、测试轮次、追逐与结局分支 | 成员 B |
| 报告与证据 | 进步报告、文本变化、证据收集与证据板 | 成员 C |
| 共享部分 | 游戏入口、路由、全局样式、公共组件、项目配置 | 指定整合负责人 |

以上负责人只是初步建议，请三人确认后再作为正式分工。

## 4. 冲突预防

- 不要同时修改同一个共享文件，尤其是主入口、路由、全局 CSS 和依赖配置。
- 如果模块需要共享文件变更，先在群里说明，由整合负责人统一处理。
- 尽量把功能写在各自模块目录中，通过清晰接口连接。
- 合并前先同步主分支；遇到冲突先暂停，不要盲目选择覆盖某一方。
- 任何合并都要在本地重新启动游戏，检查受影响流程。
