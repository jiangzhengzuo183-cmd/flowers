# Maze 01 机关与立体灰模

2026-11-04 第四版：新增西北半下沉花庭与起伏回廊；中心改为三入口欧式圆形小教堂，墙身 5.8m、尖顶 11.2m（尖饰约 12m）；补齐高低墙、8 处嵌墙拱门、4 扇机关门和 H1–H6 六处高低空间。教堂底层净直径仍约 6.2m，通过拉高比例改善原先过矮、过宽的观感，保留道路与接口。

独立场景：`godot/scenes/levels/maze_01_greybox.tscn`。旧迷宫场景、原始 JSON、人物模型及其他成员模块保留。本机原工程的默认迷宫入口已经指向此场景，原 godot/project.godot 不覆盖；按 F5 即可试玩新版。

## 打开与操作

Windows 可双击本分支根目录的 `试玩Maze01灰模.cmd`；`编辑Maze01灰模.cmd` 打开编辑器并选中新场景。脚本优先使用本机已有的便携 Godot，也支持 PATH 中的 `godot.exe`。未找到引擎时会给出手动导入提示，不会安装软件。

获得本次完整源码后，在 Godot 中导入原来的 `godot/project.godot`，按 F5 运行整个工程；也可打开 `scenes/levels/maze_01_greybox.tscn` 运行当前场景：Windows 为 F6，macOS 为 Command+R。无需新建工程。

- WASD／方向键移动，Shift 跑步，空格跳跃（可边跑边跳）；鼠标拖动与滚轮调整视角。
- 靠近带 S 编号的开关，按 E 打开同号 D 门。需要距离足够近，并且中间没有墙。
- 门向上升起，开门音与标牌反馈，开启后保持。
- “回到入口”只重置人物；“重置关卡与机关”关闭四扇门、恢复开关并回入口。
- “灰模检查位置…”提供各高低区域、教堂三门与室内检查点；可选“教堂北侧外观”“桥段外观”检查本轮修改，也可看教堂或西北庭院总览。传送不自动开门，不计入通关测试。
- 行走进入教堂时镜头跟入室内，屋顶和墙体始终不透明。室内可继续鼠标旋转、滚轮微调；需要查看全局时使用全图查看按钮。“俯视全貌”仅作为制作检查隐藏屋顶，以便查看圆形平面；全图斜视显示尖顶。重置视角恢复全局观察范围。
- 原 A/B 线用于观察原地图的参考走向，随高低表面绘制；没有把机关往返计入原来的 60/92 步。

## 与设计图的尺寸调整

为让角色从相邻通道转入台阶、从下桥处转向 D3，坡道两端各留平地，护栏不压住这些转角入口。H1 两端坡段各约 4m，中间平台约 2.4m，最高仍为 1.2m。H2 入口落脚区、1.9m 转角平台和桥侧平台保留。

H2 上桥西坡已放缓到约 33 度，中间转角标高 2.0m；北向短坡延长到 1m，从 2.0m 接至 2.6m。另一侧下桥坡仍约 36 度。人物最大可走坡面为 40 度，全部坡面已经双向实际行走验证；不依赖跳跃或位置吸附。H3 两端和 H4 西端留地面转角净空，避免护栏挡住旧路转弯。斜坡上水平速度自然降低，动画仍按实际位移切换。

桥面厚约 0.2m，桥下改为浅圆拱形通道，拱顶净高 2.4m、拱脚净高 1.85m、净宽约 1.82m，当前人物碰撞高度为 1.6m。桥下北侧挡墙与平桥端点对齐，避免凸出到下行坡面。桥下已实际走通，不能从侧面直接上桥。

两条主要路线、入口与出口以 1.1–1.25m 矮墙为主。G1–G5 沿原墙线向门洞两侧延伸约 1–2 格（2.4–4.8m），局部带转角，外沿用约 2m 中墙过渡。中心建筑向北、东北、西北、西、东、西南、东南方向配置墙组：新增 14 段约 3m 高墙和 10 段约 2.2m 中墙，使中部向外延伸的结构更连续。高度配置共 36 段普通高墙、23 段中墙过渡，不含拱门、教堂和机关构件；桥旁的重叠部分另作裁切。入口出生点背后及侧边、出口远离拱门的路段仍保持低墙。

`arch_wall_extensions` 明确记录每个拱门的相连墙组；仅改变原墙高度，不新增封路墙，不修改道路链接。G6–G8 属于教堂自身入口，旧矩形用地边界仍为低墙。西北观察窗约 2.4m，挡土墙和栏杆保持功能。沿抬高通路的墙顶仍随步行面提高，防止高台侧面出现可越过的边界。

`central_wall_extensions` 记录中部墙组。机关门框、门杆、开关底座和高低通路护栏统一使用墙体灰色 `747e80`；只保留开关指示灯的小面积状态色。教堂外墙、圆环基座/檐口、壁柱、窗框、入口拱框和门廊平顶统一使用原外墙奶油白 a9a99c；尖顶及其顶饰保留原配色，窗内凹面保留深色。

桥段周围的普通墙只在护栏已有碰撞的平行区间移除或裁切，共处理 31 个原墙面。平台侧板与护栏承担对应阻挡，剩余端头按实际落脚高度改为低收边，避免遗留高短板；桥下分流挡墙和必要的端头阻挡保留。原始地图 JSON 和逻辑墙矩阵不改，独立灰模在运行时由新结构替代这些重复墙面。

室外遮挡保持用户选择的俯角和朝向。从摄像机向查理脚部、胸部、头部及左右轮廓共发射 9 条物理检测线，至少约 85% 检测线被普通墙挡住时，才将实际遮挡墙组半透明；有明显身体部分露出时，墙保持不透明。转出接近完全遮挡的状态后恢复，带轻微阈值差和 0.1 秒等待防止抖动。普通墙按独立段、普通拱门按门墙组合处理。机关栅门的整块移动碰撞盒不被当作视觉实墙，因为栏杆缝隙仍能看见人物。查理仅仅靠近墙时不会触发透明。

命中的整段墙使用真正的 Alpha 混合，材质不透明度平滑降至约 22%；保留墙体形状，不模糊、不挖洞、不使用点阵裁切。转动镜头后不再遮挡时恢复原始不透明材质，全图查看也恢复原始材质。为了避免边缘抖动，仅保留 0.1 秒恢复等待。所有人物碰撞和机关视线阻挡保持，不会允许穿墙或隔墙开门。

圆厅、门廊及 G6–G8 建筑入口完全排除半透明处理，保留实体镜头碰撞。进门时平滑进入室内跟随配置：默认跟随距离约 2.1m、视野约 66 度，窄门廊近墙时适当放宽，最高约 84 度，焦点略降以保留脚下取景余量。摄像机从真实门口进入，不穿透墙，也不通过隐藏屋顶看人物。镜头周围约 12cm 的检测余量避免近裁面伸入门柱。用户旋转朝向和俯角仍保留，手动范围为轻微仰视 −15° 至俯视 85°；默认仍为 0.68 弧度俯角、2.8m 距离。没有自动转向或因高墙切换俯视。

普通迷宫墙不再触发镜头收缩；桥面、地面、实体顶棚及教堂建筑保留镜头阻挡，沿原角度平滑收放。遇建筑实体时优先保证不穿墙。手动重置视角、制作检查传送可以立即定位。

## H6 下沉石廊、拱桥与接缝修复

H6 对应西侧 [6,1]–[11,1] 六格直廊，x=2.4–4.8、z=14.4–28.8，总长 14.4m、净宽约 2.1m。北端和南端各留 1.7m 地面转角，原向西接口的格心标高保持 0m；两段缓坡各长 2.4m，中间 6.2m 为 −0.6m 下沉平地。底部使用连续三角面碰撞，原地板在这个范围真正挖空。两侧原隔墙向下延伸，不增加岔路、捷径或机关。原 B 线经过此段，A 线不经过。

东墙有三处真正凹入约 0.1m 的浅拱壁龛，龛背仍有约 0.2m 实体墙。中龛保留无碰撞、无交互的 Marker3D：SunkenCorridor/H6_InvestigationAnchor，后续道具或调查功能可从此局部锚点接入；目前没有道具要求。墙脚和地面铺边为灰模细节，路段保持干燥、露天。

主地面与 H6 均使用浅灰 c3c8c7；普通地板保留 BoxMesh 原受光方式，避免改成多边形后地面出现深灰观感。西北花庭已有的分区占位色不变。H6 制作标签仅全图检查显示，不在低角度跟随镜头前遮挡人物。

H2 桥下采用实际弧形截面的拱顶与匹配碰撞，保留原东西向下层通道、南北向上层桥面、护栏和分流墙。最高净空 2.4m、两侧拱脚 1.85m，现有 1.6m 人物不需要跳跃。桥面高度与 D4 门、S3 平台不变。

教堂圆厅与门廊地板合成无重叠的单一表面；门廊屋顶裁切成互不覆盖的部分；相邻门廊共用的墙面仅生成一次；圆墙和门廊墙在 G6–G8 门柱处裁切，由原门框承担该部分实体，去掉重叠的可见面。碰撞和三门通路保留。后续复核还发现圆环基座与檐口在门廊内墙上残留共面切口。两圈装饰在门廊墙外 1cm 收口，原地面、灯光和材质配色不变；同一原生视角开/关阴影对比确认墙脚斑块消失（building_seams_before.png / building_seams_final.png），并对对应墙脚、檐口的实际三角面加入单覆盖检查。本轮门廊平顶仍为无重叠的矩形拼块，采用与外墙相同的奶油白和正确受光的 BoxMesh；不把平顶当作尖顶的深色材质处理。修复针对已定位的共面闪烁，未替换正式材质或更换渲染模式。

## 文件与接口

- `godot/data/levels/maze_01_greybox.json`：基准地图路径、17 处墙体差异、八拱门、四门与开关、六个高低空间、圆形教堂参数和高低墙分区。
- `godot/scenes/levels/maze_01_greybox.tscn`：继承旧迷宫的独立试玩场景。
- `godot/scenes/levels/greybox_gate.tscn`、`greybox_switch.tscn`：可复用机关场景。
- `godot/scripts/levels/maze_01_layout.gd`：只在内存中应用墙体补丁，维护独立的上下层连通模型。height_at(point) 在 H6 范围优先返回负标高；桥区仍返回原上层高度，原桥下单独的连通节点不变。
- `greybox_generator.gd`：复用原生成器，添加新建筑、坡面、护栏与随高度变化的参考线；普通墙改为独立网格和碰撞体，供视线命中后逐段透明。
- `round_hall.gd`：独立圆形教堂构件；`build(parent,spec)` 建立圆墙、门廊和尖顶，`contains(point,spec)` 供镜头判断室内。仅由灰模模块调用。
- `sunken_corridor.gd`：独立长廊构件，build(parent,spec) 返回连续地面三角面；三处壁龛与调查物锚点随构件生成。
- `arched_underpass.gd`：独立桥洞构件，build(parent,spec) 生成浅圆拱顶、两侧拱口和原分流挡墙。
- `greybox_geometry.gd`：盒体、凸体、平面表面、沿 X 轴挤出的截面、文字与开门声的公共构件。
- `greybox_gate.gd`：`open_gate()`、`reset_gate()`、`is_open`、`opened` 信号。
- `greybox_switch.gd`：`gate_id`、`used`、`set_used()`。
- `greybox_scene.gd`：E 交互、视线检查、门状态、检查位置、机关复位与出口检测。
- `greybox_player.gd`：继承原人物控制，仅为坡道配置贴地与最大坡角。
- `greybox_camera.gd`：室内外跟随配置的平滑过渡、门廊与顶棚碰撞、近墙取景；保持用户俯角和朝向。
- `wall_plan.gd`：圆墙和门廊接缝的凸多边形裁切工具，仅由灰模构件调用。
- `wall_occlusion.gd`、`wall_occlusion.gdshader`：独立视线遮挡模块；由灰模场景以 `configure(generator,player,rig,settings={})` 接入，`sight_blockers(camera_position)` 只返回达到近乎全遮挡阈值时的普通墙组。阈值、不透明度和恢复等待从 JSON 的 `occlusion` 读取；室内配置从 `camera` 读取。建筑材料始终不透明，不修改人物、美术源资源或共享主题。
- `godot/tests/levels/check_maze_01_greybox.gd`：新关卡分状态图检查和实际人物通行测试。

物理层约定仅在该场景内使用：人物在第 2 层，检测第 1 层；全部阻挡物保留第 1 层。可渐隐的普通墙体移除第 3 层镜头查询标记，教堂建筑、地面、桥面、实体顶棚保留第 1、3 层。镜头只查询第 3 层，角色和机关视线仍检测第 1 层。未改共享项目的物理层名称或输入映射。

RaisedSurfaceCollision 把相邻台阶坡面与转角平台拼成统一静态三角面碰撞，移除内部连接面的阻挡；外围侧面、桥底和护栏保留碰撞。这样处理坡道接平台时胶囊可能卡住的接缝。
